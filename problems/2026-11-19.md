## Problem 1: Sensor Window Maximum

**Topic:** Queues — sliding window maximum with a monotonic deque

**Statement:** A temperature sensor on a production line reports one reading per second. Given the readings `nums` and a window size `k`, return the maximum reading in every consecutive window of `k` readings. The output has one value per window, in order. Aim for O(n) time overall — a naive scan of each window is too slow for a long telemetry stream, so think about what information about a window you actually need to keep as it slides by one reading.

```cpp
std::vector<int> maxSlidingWindow(const std::vector<int>& nums, int k);
```

**Example 1:**

```
Input:  nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3
Output: [3, 3, 5, 5, 6, 7]
Explanation: Windows are [1,3,-1], [3,-1,-3], [-1,-3,5], [-3,5,3], [5,3,6], [3,6,7].
```

**Example 2:**

```
Input:  nums = [1], k = 1
Output: [1]
Explanation: A single reading is the maximum of its own window.
```

**Example 3:**

```
Input:  nums = [9, 8, 7, 6, 5], k = 2
Output: [9, 8, 7, 6]
Explanation: The readings are strictly decreasing, so each window's maximum is its first element.
```

**Example 4:**

```
Input:  nums = [4, 4, 4, 4], k = 3
Output: [4, 4]
Explanation: Equal readings are all maxima; duplicate values must not break the window bookkeeping.
```

**Constraints:**
- `1 <= nums.size() <= 10^5`
- `1 <= k <= nums.size()`
- `-10^4 <= nums[i] <= 10^4`
- Aim for O(n) time and O(k) extra space

## Problem 2: Firmware Symbol Table Skip List

**Topic:** Design — probabilistic skip list with expected O(log n) search, insert, and erase

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A firmware loader keeps a symbol table mapping 32-bit symbol IDs to their load addresses. Design a class `SymbolTable` backed by a skip list (a layered linked list where each node is promoted to higher levels with probability 1/2) that supports three operations: `search(id)` returns the load address for `id`, or -1 if the ID is not present; `add(id, address)` inserts the pair, or updates the address if `id` already exists; `erase(id)` removes the ID and returns `true` if it was present (otherwise returns `false`). Your implementation must not use `std::map`, `std::unordered_map`, `std::set`, or any other balanced-tree/hash container — the skip list structure itself is the point. Use a fixed maximum level (16 is enough for the given limits) and a deterministic random promotion rule you can explain.

```cpp
class SymbolTable {
public:
    int search(int id);
    void add(int id, int address);
    bool erase(int id);
};
```

**Example 1:**

```
Input:
SymbolTable table;
table.add(10, 0x1000);  // insert symbol 10 at 0x1000
table.add(20, 0x2000);  // insert symbol 20 at 0x2000
table.add(30, 0x3000);  // insert symbol 30 at 0x3000
table.search(20);       // returns 0x2000
table.search(15);       // returns -1 (symbol 15 not present)
table.add(20, 0x2A00);  // update symbol 20 to 0x2A00
table.search(20);       // returns 0x2A00
table.erase(20);        // returns true
table.search(20);       // returns -1
table.erase(20);        // returns false (already removed)
```

**Example 2:**

```
Input:
SymbolTable table;
table.add(5, 100);   // insert symbol 5
table.add(5, 200);   // update symbol 5 in place — still one entry
table.search(5);     // returns 200
table.erase(5);      // returns true
table.search(5);     // returns -1
```

**Constraints:**
- `0 <= id <= 2^31 - 1`
- `-2^31 <= address <= 2^31 - 1`
- At most `5 * 10^4` total calls to `search`, `add`, and `erase`
- Each operation must run in O(log n) expected time
- Do not use `std::map`, `std::unordered_map`, `std::set`, or any other balanced-tree/hash container
