## Problem 1: Longest Common Subsequence of Firmware Logs

**Topic:** Dynamic programming — longest common subsequence

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** Two firmware versions log event codes as sequences of integers. The logs are not identical, but they share a common history: some event codes appear in both logs in the same relative order (not necessarily consecutively). Find the length of the longest common subsequence of the two logs — the longest sequence of event codes that appears as a subsequence in both logs. Return only the length.

```cpp
int longestCommonLogSequence(const std::vector<int>& logA, const std::vector<int>& logB);
```

**Example 1:**

```
Input:  logA = [1, 3, 4, 1, 2, 3]
        logB = [3, 4, 1, 2, 1, 3]
Output: 5
Explanation: The subsequence [3, 4, 1, 2, 3] appears in both logs in order,
so the longest common subsequence has length 5.
```

**Example 2:**

```
Input:  logA = [5, 1, 3]
        logB = [2, 4, 6]
Output: 0
Explanation: The logs share no event code, so there is no common subsequence.
```

**Example 3:**

```
Input:  logA = [7, 7, 7]
        logB = [7, 7]
Output: 2
Explanation: The common subsequence is [7, 7]; it cannot be longer than the
shorter log.
```

**Example 4:**

```
Input:  logA = []
        logB = [1, 2, 3]
Output: 0
Explanation: An empty log shares nothing with any other log.
```

**Constraints:**
- `0 <= logA.size(), logB.size() <= 1000`
- Each event code is an integer in the range `[0, 10^9]`
- Aim for O(m * n) time, where m and n are the two log lengths
- Stretch goal: use O(min(m, n)) extra space

## Problem 2: Evaluate a Postfix Telemetry Expression

**Topic:** Stacks — reverse Polish notation evaluation

**Statement:** A sensor gateway receives arithmetic expressions in postfix (reverse Polish) notation as a list of string tokens. Each token is either an integer (possibly negative, possibly multi-digit) or one of the four operators `+`, `-`, `*`, `/`. Evaluate the expression and return the integer result. Division truncates toward zero, as in C++ integer division. The expression is always valid: every operator has enough operands on the stack, and exactly one value remains at the end.

```cpp
int evaluatePostfixExpression(const std::vector<std::string>& tokens);
```

**Example 1:**

```
Input:  tokens = ["2", "1", "+", "3", "*"]
Output: 9
Explanation: (2 + 1) * 3 = 9.
```

**Example 2:**

```
Input:  tokens = ["4", "13", "5", "/", "+"]
Output: 6
Explanation: 13 / 5 = 2 (truncated toward zero), then 4 + 2 = 6.
```

**Example 3:**

```
Input:  tokens = ["10", "6", "9", "3", "+", "-11", "*", "/", "*", "17", "+", "5", "+"]
Output: 22
Explanation: 9 + 3 = 12; 12 * -11 = -132; 6 / -132 = 0; 10 * 0 = 0;
0 + 17 = 17; 17 + 5 = 22.
```

**Example 4:**

```
Input:  tokens = ["3", "-4", "+", "2", "*"]
Output: -2
Explanation: (3 + -4) * 2 = -2. Note that "-4" is a negative operand, not an operator.
```

**Constraints:**
- `1 <= tokens.size() <= 10^4`
- Each token is either an integer in the range `[-200, 200]` or one of `+`, `-`, `*`, `/`
- The expression is always valid and division by zero never occurs
- All intermediate results fit in a 32-bit signed integer
- Aim for O(n) time and O(n) extra space, where n is the number of tokens
