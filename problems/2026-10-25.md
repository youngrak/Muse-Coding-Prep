## Problem 1: Firmware Version Comparator (Google Doc mode)

**Topic:** strings / parsing

**Google Doc mode:** solve this one in a plain text editor with no compiling — dry-run your code by hand, tracing through the examples and edge cases before sending it back.

**Statement:** A fleet of devices reports firmware versions as dot-separated numeric strings, e.g. "2.10.3". Leading zeros are allowed ("2.01" equals "2.1"), and a missing revision is treated as zero ("2.1" equals "2.1.0"). Write a function that compares two version strings and returns -1 if the first is older, 1 if the first is newer, and 0 if they are equal. Versions may have different numbers of components, and individual components can be large (do not rely on converting a whole component with a fixed-width integer type if it might overflow — handle arbitrary-length numeric components safely).

```cpp
int compareVersions(const std::string& v1, const std::string& v2);
```

**Examples:**

```
compareVersions("2.10.3", "2.9.12")  -> 1
compareVersions("1.0", "1.0.0")      -> 0
compareVersions("3.01", "3.1.0")     -> 0
compareVersions("1.2", "1.10")        -> -1
```

**Constraints:**

- Each version string has length 1..100 and consists of digits and dots only.
- No leading or trailing dots; no empty components.
- Each numeric component may have up to 20 digits.
- Time complexity O(n + m), extra space O(1) where n and m are the input lengths.

## Problem 2: Telemetry Rate Limiter

**Topic:** design (small class design)

**Statement:** A gateway device uploads telemetry batches to the cloud, but the backend accepts at most K uploads in any sliding window of W seconds. Design a class that decides, for each upload request arriving with a timestamp (seconds, non-decreasing across calls), whether the upload is allowed. An allowed request counts toward the limit; a rejected request does not. The limiter must support many devices efficiently: do not rescan the full history on every request. Implement the class with the interface below, using any internal data structure you like.

```cpp
class RateLimiter {
 public:
  RateLimiter(int maxRequests, int windowSeconds);
  bool allow(int timestampSeconds);
};
```

**Examples:**

```
RateLimiter rl(3, 10);
rl.allow(1)   -> true    // 1 upload in window
rl.allow(2)   -> true
rl.allow(3)   -> true
rl.allow(4)   -> false   // 3 already in the last 10 seconds
rl.allow(12)  -> true    // request at t=1 has slid out of the window
```

**Constraints:**

- 1 <= maxRequests <= 10^6, 1 <= windowSeconds <= 10^6.
- Timestamps are integers in seconds, non-decreasing across calls, starting at 0 or later.
- The total number of allow() calls can be large; each call should be amortized O(1).
- State your time and space complexity in a comment.
