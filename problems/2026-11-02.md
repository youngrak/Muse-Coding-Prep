## Problem 1: Firmware Memory Allocator

**Topic:** Design — first-fit memory allocator with block coalescing

**Mode:** Google Doc mode — solve in a plain text editor with no compiling, and dry-run by hand.

You are writing the memory manager for a firmware image that runs out of a fixed-size SRAM pool. There is no operating system to ask for more memory, so your allocator must manage one contiguous pool of `capacity` bytes itself.

Implement a first-fit allocator with the following behavior:

- `allocate(size)` returns the start offset of the first free block large enough to hold `size` bytes, scanning from the lowest offset upward. If no free block is large enough, return `-1`. A block that is larger than requested is split: the front part is handed out and the remainder stays free.
- `release(offset)` frees the block that starts at `offset` and merges it with any immediately adjacent free blocks (coalescing), so that a later large allocation can reuse the combined space.
- Offsets are zero-based. `release` is only ever called with an offset previously returned by a successful `allocate` that has not been released yet.

```cpp
class MemoryAllocator {
public:
    MemoryAllocator(int capacity);
    int allocate(int size);
    void release(int offset);
};
```

**Examples:**

```cpp
MemoryAllocator alloc(100);
alloc.allocate(10);  // returns 0
alloc.allocate(20);  // returns 10
alloc.release(0);    // frees [0, 10)
alloc.allocate(5);   // returns 0  (split of the freed block)
alloc.allocate(8);   // returns 30 (the [5, 10) remainder is too small)
alloc.allocate(200); // returns -1 (no block large enough)
```

**Constraints:**

- `1 <= capacity <= 100000`
- `1 <= size <= capacity`
- At most `10000` calls to `allocate` and `release` combined.
- `release` is called only with a currently allocated offset.

## Problem 2: Lowest Common Ancestor in a Device Hierarchy

**Topic:** Trees — lowest common ancestor in a binary tree

A device fleet is organized as a binary hierarchy tree: each node is a device, its left and right children are its subordinate devices, and the root is the fleet gateway. Given the root and two devices `p` and `q` (both guaranteed to be present in the tree), find their lowest common ancestor — the deepest device that is an ancestor of both `p` and `q`. A device is considered an ancestor of itself.

```cpp
struct TreeNode {
    int id;
    TreeNode* left;
    TreeNode* right;
};

TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q);
```

**Examples:**

```
Tree (by id):
        10
       /  \
      4    20
     / \     \
    2   7     30

lowestCommonAncestor(root, node 2, node 7)  -> node 4
lowestCommonAncestor(root, node 2, node 30) -> node 10
lowestCommonAncestor(root, node 20, node 30) -> node 20
```

**Constraints:**

- The tree has between `2` and `10000` nodes.
- Node ids are unique.
- Both `p` and `q` are present in the tree.
- Solve it in a single traversal if you can; state the time and space complexity of your approach.
