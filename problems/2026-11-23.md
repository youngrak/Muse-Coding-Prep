## Problem 1: Sensor Network Maximum Flow

**Topic:** Graphs — maximum flow (Edmonds-Karp)

**Statement:** A sensor mesh routes telemetry from a gateway (source) to a data sink. Each directed link has a bandwidth capacity in packets per second. Compute the maximum total throughput the network can carry from the gateway to the sink without exceeding any link's capacity. Flow can split across multiple paths, and a link's unused capacity in either direction can be reclaimed by rerouting flow, so the residual graph matters. Implement Edmonds-Karp (BFS-based Ford-Fulkerson) or an equivalent max-flow algorithm. The capacity matrix is given as an adjacency matrix: `capacity[i][j]` is the capacity of the directed link from node `i` to node `j` (0 means no link).

```cpp
int maxSensorThroughput(int numNodes, int source, int sink, const std::vector<std::vector<int>>& capacity);
```

**Example 1:**

```
Input:  numNodes = 4, source = 0, sink = 3
        capacity = [[0, 3, 2, 0],
                    [0, 0, 5, 2],
                    [0, 0, 0, 3],
                    [0, 0, 0, 0]]
Output: 5
Explanation: Send 2 units on 0 -> 1 -> 3, 1 unit on 0 -> 1 -> 2 -> 3, and 2 units on
0 -> 2 -> 3. The gateway's total outgoing capacity is 3 + 2 = 5, so 5 is the maximum.
```

**Example 2:**

```
Input:  numNodes = 3, source = 0, sink = 2
        capacity = [[0, 5, 0],
                    [0, 0, 0],
                    [0, 0, 0]]
Output: 0
Explanation: No path reaches the sink, so no flow is possible.
```

**Example 3:**

```
Input:  numNodes = 3, source = 0, sink = 2
        capacity = [[0, 7, 0],
                    [0, 0, 4],
                    [0, 0, 0]]
Output: 4
Explanation: The single path 0 -> 1 -> 2 is bottlenecked by the 1 -> 2 link of capacity 4.
```

**Example 4:**

```
Input:  numNodes = 4, source = 0, sink = 3
        capacity = [[0, 5, 5, 0],
                    [0, 0, 0, 5],
                    [0, 0, 0, 5],
                    [0, 0, 0, 0]]
Output: 10
Explanation: Two disjoint paths each carry 5 units: 0 -> 1 -> 3 and 0 -> 2 -> 3.
```

**Constraints:**
- `2 <= numNodes <= 100`
- `0 <= capacity[i][j] <= 10^4`
- `capacity[i][i] == 0`
- `source != sink`
- Aim for O(V * E^2) time (Edmonds-Karp) or better

## Problem 2: Firmware Allowlist Bloom Filter

**Topic:** Design — Bloom filter (probabilistic membership)

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A firmware device keeps an allowlist of trusted command IDs, but memory is tight, so instead of storing every ID exactly, it uses a Bloom filter: a fixed-size bit array plus k independent hash functions. Design a class that supports inserting a command ID and testing whether an ID might be in the allowlist. False positives are allowed (the filter may say an ID is present when it is not), but false negatives are not (if an ID was inserted, the filter must always report it as possibly present). Choose the number of hash functions k from the bit-array size m and the expected number of items n, using the standard optimal value k = (m / n) * ln 2 (at least 1). Also implement a method that estimates the current false-positive probability from the number of items actually inserted so far, using the standard formula (1 - e^(-k * n / m))^k. Hash with std::hash combined with a simple mixing step (for example double hashing); do not rely on a cryptographic hash.

```cpp
class FirmwareAllowlist {
public:
    FirmwareAllowlist(size_t bitArraySize, size_t expectedItems);
    void insert(uint32_t commandId);
    bool mightContain(uint32_t commandId) const;
    double estimatedFalsePositiveRate() const;
};
```

**Example 1:**

```
Input:  FirmwareAllowlist filter(1000, 100);
        filter.insert(42); filter.insert(7); filter.insert(13);
Output: filter.mightContain(42) == true
        filter.mightContain(7) == true
        filter.mightContain(13) == true
Explanation: Every inserted ID must always test positive — no false negatives.
```

**Example 2:**

```
Input:  FirmwareAllowlist filter(1000, 100);
        // insert 100 distinct IDs, then:
        filter.estimatedFalsePositiveRate()
Output: approximately 0.008
Explanation: With m = 1000, n = 100, the optimal k is about 7, and
(1 - e^(-7 * 100 / 1000))^7 is about 0.008. Any value within +/- 0.003 of the
theoretical value is acceptable.
```

**Example 3:**

```
Input:  FirmwareAllowlist filter(1000, 100);
        // nothing inserted yet
Output: filter.mightContain(42) == false
        filter.estimatedFalsePositiveRate() == 0.0
Explanation: An empty filter contains nothing, so the false-positive rate is zero.
```

**Example 4:**

```
Input:  FirmwareAllowlist filter(1000, 100);
        filter.insert(42); filter.insert(42);
Output: filter.mightContain(42) == true
Explanation: Inserting the same ID twice must not break anything; it still tests positive.
```

**Constraints:**
- `1 <= bitArraySize <= 10^6`
- `1 <= expectedItems <= 10^5`
- `commandId` is a 32-bit unsigned integer
- `insert` and `mightContain` must each run in O(k) time, where k is the number of hash functions
- `estimatedFalsePositiveRate()` must reflect the number of items actually inserted so far, not just the expected count
