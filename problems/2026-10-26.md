## Problem 1: Deep-Sleep Wake-Up Scheduler

**Topic:** Greedy — interval scheduling

A battery-powered sensor node wakes up to run jobs, then goes back to sleep. Each job has a start time and an end time, in minutes. The node can run only one job at a time, so jobs may not overlap — but a job that ends at time t and another job that starts at time t can both run. Given the list of requested jobs, return the maximum number of jobs the node can complete.

**Required signature:**

```cpp
int maxCompletedJobs(const std::vector<std::pair<int,int>>& jobs);
```

**Examples:**

```text
maxCompletedJobs({{0,30},{5,10},{15,20},{10,15}})  -> 3   // (5,10), (10,15), (15,20)
maxCompletedJobs({{1,4},{3,5},{0,6},{5,7}})        -> 2   // (1,4), (5,7)
maxCompletedJobs({})                             -> 0
```

**Constraints:**

- 0 <= jobs.size() <= 2 * 10^5.
- For each job, 0 <= start < end <= 10^9.
- The input order is arbitrary; jobs are not sorted.
- Expected time complexity O(n log n), extra space O(1) besides sorting.

## Problem 2: Redundant Sensor Link

**Topic:** Disjoint set union (union-find)

A sensor mesh has n nodes numbered 0 to n-1 and starts with no links. Links between nodes are added one at a time, in the order given. A link is redundant if its two endpoints are already connected to each other through previously added links, so adding it would create a cycle. Return the first redundant link as a two-element vector {u, v}. If no link is redundant, return an empty vector.

**Required signature:**

```cpp
std::vector<int> firstRedundantLink(int n, const std::vector<std::pair<int,int>>& links);
```

**Examples:**

```text
firstRedundantLink(4, {{0,1},{1,2},{2,3},{3,1}})  -> {3, 1}  // 3 and 1 already connected via 3-2-1
firstRedundantLink(3, {{0,1},{1,2}})             -> {}      // no cycle is ever formed
```

**Constraints:**

- 1 <= n <= 10^5; 0 <= links.size() <= 2 * 10^5.
- Every link has two distinct endpoints in [0, n).
- The same pair of nodes may appear more than once; the second occurrence is redundant.
- Expected time complexity close to O(n + links) — a fresh graph traversal per link is too slow.
