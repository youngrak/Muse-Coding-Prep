## Problem 1: Sensor Alert Span

**Topic:** Stacks (monotonic stack)

**Google Doc mode: solve this one in a plain text editor with no compiling, and dry-run it by hand.**

A temperature sensor reports one reading per second. For each reading, define its alert span as the number of consecutive readings ending at that reading (including itself) whose values are less than or equal to the current reading. In other words, look backwards from the current reading and count how many readings you pass before hitting a reading strictly greater than the current one.

```cpp
vector<int> sensorAlertSpan(const vector<int>& readings);
```

**Example:**

```
Input:  readings = [100, 80, 60, 70, 60, 75, 85]
Output: [1, 1, 1, 2, 1, 4, 6]
```

**Constraints:**

- 1 <= readings.size() <= 100,000
- 0 <= readings[i] <= 1,000,000,000
- Your solution should run in O(n) time and O(n) auxiliary space.

## Problem 2: Sensor Range Sum Aggregator

**Topic:** Trees / data structures (segment tree or Fenwick tree)

A data logger stores one energy reading per sensor channel. Readings are corrected over time, so individual values change. Implement a class that supports point updates and range-sum queries over the readings, so a monitoring dashboard can ask for the total energy across any contiguous block of channels at any moment.

```cpp
class SensorAggregator {
public:
    SensorAggregator(const vector<int>& readings);
    void update(int index, int value);
    int rangeSum(int left, int right);
};
```

**Example:**

```
SensorAggregator agg({3, 1, 4, 1, 5});
agg.rangeSum(1, 3);  // returns 6  (1 + 4 + 1)
agg.update(2, 10);
agg.rangeSum(1, 3);  // returns 12 (1 + 10 + 1)
```

**Constraints:**

- 1 <= readings.size() <= 100,000
- Each reading value fits in a 32-bit signed int; the sum of a range may exceed it, so choose your return type accordingly.
- Up to 100,000 update and rangeSum calls in total.
- Each update and each query should run in O(log n) time.
