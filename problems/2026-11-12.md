## Problem 1: Firmware Log Edit Distance

**Topic:** Dynamic programming — edit distance

**Statement:** Two firmware builds log their boot events as strings of lowercase event codes. One log can be turned into another with single-character edits: insert a character, delete a character, or replace one character with another. Given two logs `a` and `b`, return the minimum number of edits needed to transform `a` into `b`.

```cpp
int minEditDistance(const std::string& a, const std::string& b);
```

**Example 1:**

```
Input:  a = "calib", b = "cable"
Output: 3
Explanation: Replace 'l' with 'b', 'i' with 'l', and the final 'b' with 'e'.
```

**Example 2:**

```
Input:  a = "sensor", b = "sensor"
Output: 0
```

**Example 3:**

```
Input:  a = "", b = "boot"
Output: 4
```

**Constraints:**
- `0 <= a.length(), b.length() <= 500`
- `a` and `b` consist of lowercase English letters.

## Problem 2: Lock-Free SPSC Sensor Ring Buffer

**Topic:** Concurrency — atomics, single-producer single-consumer lock-free ring buffer

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A sensor interrupt handler (the single producer) writes samples into a fixed-capacity ring buffer, and a single consumer thread drains it. Implement a lock-free single-producer single-consumer (SPSC) ring buffer for `int` samples. The capacity is a power of two, fixed at construction. `tryPush` returns `false` when the buffer is full, and `tryPop` returns `false` when it is empty. No mutexes, condition variables, or blocking calls are allowed, and no memory may be allocated after construction. Use `std::atomic` for the head/tail indices and choose memory orderings that make the buffer correct under concurrent producer/consumer access.

```cpp
class SpscSensorBuffer {
public:
    explicit SpscSensorBuffer(size_t capacity); // capacity must be a power of two
    bool tryPush(int sample);
    bool tryPop(int& sample);
    bool empty() const;
    bool full() const;
    size_t size() const;
private:
    // ... your members
};
```

**Example 1:**

```
SpscSensorBuffer buf(4);
buf.tryPush(10); // returns true
buf.tryPush(20); // returns true
buf.tryPush(30); // returns true
int v;
buf.tryPop(v);   // returns true, v == 10
buf.tryPush(40); // returns true
buf.tryPush(50); // returns true
buf.tryPush(60); // returns false (buffer full: 20, 30, 40, 50)
buf.tryPop(v);   // returns true, v == 20
buf.tryPop(v);   // returns true, v == 30
buf.tryPop(v);   // returns true, v == 40
buf.tryPop(v);   // returns true, v == 50
buf.tryPop(v);   // returns false (buffer empty)
```

**Constraints:**
- `capacity` is a power of two, `2 <= capacity <= 2^20`
- Exactly one producer thread calls `tryPush`; exactly one consumer thread calls `tryPop`
- `empty()`, `full()`, and `size()` may be called from either thread
- No mutexes, condition variables, or blocking calls; no allocation after construction
