## Problem 1: Firmware Module Boot Order

*Topic: Graphs — topological sort*

**[Google Doc mode: solve in a plain text editor with no compiling; dry-run your code by hand.]**

A firmware image contains `numModules` modules numbered 0 to `numModules - 1`. Each dependency pair `(a, b)` means module `a` must be initialized before module `b`. Return any valid initialization order as a vector of module numbers. If no valid order exists because of a circular dependency, return an empty vector.

Required signature:

```cpp
std::vector<int> bootOrder(int numModules, const std::vector<std::pair<int,int>>& dependencies);
```

Examples:

```
numModules = 4, dependencies = {{0,1},{0,2},{1,3},{2,3}}  ->  [0,1,2,3] or [0,2,1,3] (any valid order)
numModules = 3, dependencies = {{0,1},{1,2},{2,0}}       ->  [] (circular dependency)
```

Constraints:

- 1 <= numModules <= 10^5
- 0 <= dependencies.size() <= 10^5
- 0 <= a, b < numModules
- A self-dependency (a, a) counts as a circular dependency
- When multiple valid orders exist, any one is accepted

## Problem 2: Lock-Free Sensor Heartbeat Counter

*Topic: Concurrency — atomics*

In a sensor-firmware logging service, many sensor threads report heartbeats concurrently while a single monitor thread periodically reads and resets the count. Design a thread-safe class `SensorHeartbeat` with two methods:

- `tick()` — called concurrently by many sensor threads; each call registers exactly one heartbeat.
- `snapshotAndReset()` — called by exactly one monitor thread; returns the number of heartbeats registered since the previous call and resets the counter to zero.

No heartbeat may be lost or double-counted. You may use atomics; do not use a mutex.

Required signature:

```cpp
class SensorHeartbeat {
public:
    void tick();
    uint64_t snapshotAndReset();
};
```

Examples:

```
4 sensor threads each call tick() 1,000,000 times; after joining, snapshotAndReset() -> 4000000
A second snapshotAndReset() called immediately after -> 0
```

Constraints:

- `tick()` may be called concurrently from any number of threads
- `snapshotAndReset()` is called from a single thread only
- Counts may reach 2^40; choose types accordingly
- No mutex — atomics only
