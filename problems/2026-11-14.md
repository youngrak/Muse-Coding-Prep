## Problem 1: Maximum Path Sum in a Sensor Tree

**Topic:** Trees — binary tree maximum path sum

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A sensor network is organized as a binary tree. Each node holds a signed calibration offset (positive or negative). A path is any sequence of nodes connected by parent-child edges, with each node visited at most once — the path does not need to pass through the root, and it does not need to end at a leaf. Return the maximum possible sum of node values along any such path. The tree has at least one node, so the answer is always the value of some non-empty path.

```cpp
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

int maxSensorPathSum(TreeNode* root);
```

**Example 1:**

```
Input:  root = [1, 2, 3]
Output: 6
Explanation: The best path is 2 -> 1 -> 3, with sum 2 + 1 + 3 = 6.
```

**Example 2:**

```
Input:  root = [-10, 9, 20, null, null, 15, 7]
Output: 42
Explanation: The best path is 15 -> 20 -> 7, with sum 15 + 20 + 7 = 42.
```

**Example 3:**

```
Input:  root = [-3]
Output: -3
Explanation: The only path is the single node -3.
```

**Example 4:**

```
Input:  root = [2, -1]
Output: 2
Explanation: The best path is the single node 2; extending it to -1 would lower the sum.
```

**Constraints:**
- `1 <= number of nodes <= 3 * 10^4`
- `-1000 <= TreeNode::val <= 1000`

## Problem 2: Parallel Sensor Data Aggregation

**Topic:** Concurrency — parallel reduction with std::thread

**Statement:** A gateway collects `N` sensor readings into a vector. Write a function that computes, in parallel, how many readings are above a threshold, the sum of all readings, and the minimum and maximum reading. Split the work across at most `numThreads` worker threads, each processing a contiguous chunk of the input, then combine the partial results. Threads must not share mutable state while they run (no data races), and the result must be identical regardless of how many threads are used. When the input is empty, return countAbove = 0, sum = 0, minVal = INT_MAX, maxVal = INT_MIN. When `numThreads` exceeds the number of readings, use fewer threads — never spawn more threads than there are elements.

```cpp
struct SensorAggregate {
    long long countAbove;
    long long sum;
    int minVal;
    int maxVal;
};

SensorAggregate aggregateSensorReadings(const std::vector<int>& readings,
                                       int threshold,
                                       int numThreads);
```

**Example 1:**

```
Input:  readings = [5, 12, 3, 20, 8], threshold = 10, numThreads = 2
Output: {countAbove = 2, sum = 48, minVal = 3, maxVal = 20}
Explanation: Readings above 10 are 12 and 20; the sum is 5 + 12 + 3 + 20 + 8 = 48.
```

**Example 2:**

```
Input:  readings = [7, 7, 7], threshold = 7, numThreads = 4
Output: {countAbove = 0, sum = 21, minVal = 7, maxVal = 7}
Explanation: No reading is strictly above 7, and only 3 threads are needed for 3 elements.
```

**Example 3:**

```
Input:  readings = [], threshold = 0, numThreads = 2
Output: {countAbove = 0, sum = 0, minVal = INT_MAX, maxVal = INT_MIN}
```

**Constraints:**
- `0 <= readings.size() <= 10^7`
- `-10^9 <= readings[i] <= 10^9`
- `1 <= numThreads <= 64`
- Spawn at most `numThreads` threads, and never more threads than elements
- No data races; the result must not depend on the thread count
