## Problem 1: Merge Overlapping Sensor Windows

**Topic:** Arrays / intervals — merge overlapping intervals

**Statement:** A sensor gateway records the active windows of its radio as half-open intervals `[start, end)` in milliseconds since boot, where `start < end`. The windows arrive unsorted and may overlap or touch (a window ending at exactly the time the next one starts counts as continuous). Merge all overlapping or touching windows into the smallest set of disjoint windows that covers exactly the same active time, and return them sorted by start time.

```cpp
std::vector<std::vector<int>> mergeSensorWindows(std::vector<std::vector<int>>& windows);
```

**Example 1:**

```
Input:  windows = [[100, 300], [50, 120], [400, 500], [250, 350]]
Output: [[50, 350], [400, 500]]
```

**Example 2:**

```
Input:  windows = [[10, 20], [20, 30], [40, 50]]
Output: [[10, 30], [40, 50]]
```

**Example 3:**

```
Input:  windows = [[5, 9]]
Output: [[5, 9]]
```

**Constraints:**
- `1 <= windows.size() <= 10^5`
- Each window is `[start, end]` with `0 <= start < end <= 10^9`.
- The output must be sorted by start time and contain no overlapping or touching windows.

## Problem 2: Sensor Calibration Barrier

**Topic:** Concurrency — reusable barrier (mutex + condition variable)

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A calibration cycle needs `N` sensor threads to all reach a checkpoint before any of them may proceed. Implement a reusable barrier: each thread calls `wait()` and blocks until all `N` threads have arrived, at which point all of them are released at once. The barrier must reset itself so the same threads can use it again for the next calibration round, with no busy-waiting (spinning) and no data races. Use only `std::mutex` and `std::condition_variable`.

```cpp
class SensorBarrier {
public:
    explicit SensorBarrier(int threadCount);
    void wait();  // blocks until all threadCount threads have called wait()
};
```

**Example:**

```
// threadCount = 3; three threads each run:
for (int round = 0; round < 2; ++round) {
    // ... collect sensor readings ...
    barrier.wait();   // no thread leaves round 0 until all 3 have arrived
    // ... use the combined readings ...
}
```

**Constraints:**
- `1 <= threadCount <= 64`
- `wait()` may be called repeatedly across many rounds by the same set of threads.
- Exactly `threadCount` threads participate in every round.
- You may add private member variables and helper methods, but you may not use any ready-made barrier primitive or busy-waiting.
- Correctly handle spurious wakeups.
