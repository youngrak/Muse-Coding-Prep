## Problem 1: Firmware Log Pattern Search

**Topic:** Strings — KMP pattern matching

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A firmware device writes a long log stream, and you need to find every occurrence of a fault-signature pattern inside it — for example, to locate every time a specific error sequence appears in a day of logs. Return all starting indices where the pattern occurs in the log. Overlapping matches count (a match may start inside a previous match). The log can be very long, so rescanning from scratch after every partial match is too slow: aim for a single linear scan that never re-examines a log character more than once.

```cpp
std::vector<int> findPatternOccurrences(const std::string& log, const std::string& pattern);
```

**Example 1:**

```
Input:  log = "ABABDABACDABABCABAB", pattern = "ABABCABAB"
Output: [10]
Explanation: The pattern occurs once, starting at index 10.
```

**Example 2:**

```
Input:  log = "AAAAA", pattern = "AA"
Output: [0, 1, 2, 3]
Explanation: Overlapping matches count — the pattern starts at every index from 0 to 3.
```

**Example 3:**

```
Input:  log = "SENSORREADSENSOR", pattern = "XYZ"
Output: []
Explanation: The pattern never occurs in the log.
```

**Example 4:**

```
Input:  log = "ABCABCABC", pattern = "ABC"
Output: [0, 3, 6]
Explanation: The pattern repeats three times back to back.
```

**Constraints:**
- `1 <= pattern.size() <= log.size() <= 10^5`
- `log` and `pattern` consist of uppercase letters and digits
- Aim for O(n + m) time and O(m) extra space, where n = log.size() and m = pattern.size()

## Problem 2: Sensor Calibration Triplet Search

**Topic:** Arrays / two pointers — 3Sum

**Statement:** A calibration routine collects a batch of sensor readings and needs every distinct combination of three readings that sums exactly to a target value — for example, to find triples of gain offsets that cancel out to a desired total. Return all unique triplets (each triplet sorted in ascending order); the order of the triplets in the result does not matter. Two triplets with the same values are duplicates even if they come from different positions in the input, so each distinct value-triplet appears only once. A brute-force check of every triple is too slow for a large batch, so aim for a quadratic solution.

```cpp
std::vector<std::vector<int>> findCalibrationTriplets(std::vector<int> readings, int target);
```

**Example 1:**

```
Input:  readings = [-1, 0, 1, 2, -1, -4], target = 0
Output: [[-1, -1, 2], [-1, 0, 1]]
Explanation: -1 + -1 + 2 = 0 and -1 + 0 + 1 = 0 are the only distinct triplets summing to 0.
```

**Example 2:**

```
Input:  readings = [0, 0, 0, 0], target = 0
Output: [[0, 0, 0]]
Explanation: Only one distinct triplet exists, even though there are four zeros.
```

**Example 3:**

```
Input:  readings = [1, 2, 3], target = 6
Output: [[1, 2, 3]]
Explanation: The only three readings sum to 6.
```

**Example 4:**

```
Input:  readings = [5, 1, 3], target = 10
Output: []
Explanation: 5 + 1 + 3 = 9, so no triplet sums to 10.
```

**Constraints:**
- `3 <= readings.size() <= 3000`
- `-10^5 <= readings[i] <= 10^5`
- `-3 * 10^5 <= target <= 3 * 10^5`
- Each triplet in the result must be sorted in ascending order, with no duplicate triplets
- Aim for O(n^2) time and O(1) extra space besides the output
