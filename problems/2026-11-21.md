## Problem 1: Maximum Coverage Between Two Sensor Towers

**Topic:** Two pointers — maximum area between two heights

**Statement:** A row of sensor towers stands along a perimeter, each tower with a given height. Pick two towers; together with the ground between them they enclose a coverage zone whose area is the distance between the two towers multiplied by the height of the shorter tower (the signal cannot rise above the shorter tower). Find the maximum coverage area achievable by any pair of towers. A brute-force check of every pair is too slow for a long row, so aim for a linear scan.

```cpp
int maxCoverage(const std::vector<int>& heights);
```

**Example 1:**

```
Input:  heights = [1, 8, 6, 2, 5, 4, 8, 3, 7]
Output: 49
Explanation: Towers 1 and 8 (0-indexed) have heights 8 and 7, distance 7, so the area is min(8, 7) * 7 = 49.
```

**Example 2:**

```
Input:  heights = [1, 1]
Output: 1
Explanation: Only one pair exists; min(1, 1) * 1 = 1.
```

**Example 3:**

```
Input:  heights = [4, 3, 2, 1, 4]
Output: 16
Explanation: The two towers of height 4 are 4 apart, giving 4 * 4 = 16.
```

**Example 4:**

```
Input:  heights = [1, 2, 1]
Output: 2
Explanation: The best pair is the towers of height 2 and 1 at distance 2, giving min(2, 1) * 2 = 2.
```

**Constraints:**
- `2 <= heights.size() <= 10^5`
- `0 <= heights[i] <= 10^4`
- Aim for O(n) time and O(1) extra space

## Problem 2: Lock-Free Sensor Event Stack

**Topic:** Concurrency — lock-free stack with atomics (Treiber stack)

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** Multiple producer threads push sensor events onto a shared stack while a consumer thread pops them, all concurrently. Implement a lock-free LIFO stack: push and pop must use no mutex or other blocking lock — only std::atomic operations (compare_exchange_weak or compare_exchange_strong) on the head pointer. Your implementation must remain correct when push and pop run concurrently on many threads: every pushed value must be popped exactly once, and pop must report empty only when the stack is truly empty at that moment. Nodes are allocated with new; popped nodes are not deleted during the test, so memory reclamation is out of scope.

```cpp
template <typename T>
class LockFreeStack {
public:
    void push(const T& value);
    bool pop(T& out);  // returns false if the stack is empty
};
```

**Example 1:**

```
LockFreeStack<int> s;
s.push(1); s.push(2); s.push(3);
int v;
s.pop(v);  // v == 3, returns true
s.pop(v);  // v == 2, returns true
s.pop(v);  // v == 1, returns true
s.pop(v);  // returns false, stack is empty
```

**Example 2:**

```
LockFreeStack<int> s;
// 8 threads each push 1000 distinct values concurrently,
// then pops collect values until the stack is empty.
// Result: all 8000 values are collected, each exactly once.
```

**Constraints:**
- `push` and `pop` must be lock-free: no std::mutex, no condition variable, no spinlock
- Use std::atomic<Node*> for the head pointer with compare_exchange_weak or compare_exchange_strong
- Aim for O(1) amortized time per push and per pop
- Nodes are allocated with new; popped nodes are not deleted during the test
- Correct under concurrent push/pop from multiple threads
