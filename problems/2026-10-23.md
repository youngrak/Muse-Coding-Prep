## Problem 1: Firmware Chunk Energy Budget

**Topic:** Dynamic programming — 0/1 knapsack

**[Google Doc mode: solve in a plain text editor with no compiling; dry-run your code by hand.]**

During an OTA maintenance window the device has a fixed energy budget. Each pending firmware chunk `i` costs `energy[i]` units to flash and carries an importance `priority[i]` (a carrier-approval weight). Pick a subset of chunks that fits the budget and maximizes total importance. Each chunk can be flashed at most once.

**Required signature:**

```cpp
int maxUpdatePriority(const std::vector<int>& energy, const std::vector<int>& priority, int budget);
```

**Examples:**

```
energy = [2, 3, 4], priority = [3, 4, 5], budget = 5  ->  7   (chunks 0 and 1)
energy = [2, 3, 4], priority = [3, 4, 5], budget = 4  ->  5   (chunk 2 alone)
energy = [5, 6],    priority = [10, 11],  budget = 4  ->  0   (nothing fits)
```

**Constraints:**

- 1 <= energy.size() == priority.size() <= 100
- 1 <= energy[i] <= 100, 1 <= priority[i] <= 1000
- 0 <= budget <= 10^4
- Aim for O(n * budget) time and O(budget) space

## Problem 2: Register Diff Analyzer

**Topic:** Bit manipulation — register comparison

When a peripheral's status register disagrees with its expected mask, firmware must report how many bits differ and which highest-order bit differs (so the most severe fault can be handled first). Given the `current` register value and the `expected` mask, compute both.

**Required signature:**

```cpp
struct RegisterDiff {
    int flipCount;      // number of differing bits
    int highestFlipped; // index of the highest-order differing bit, 0 = LSB; -1 if none differ
};
RegisterDiff analyzeRegisterDiff(uint32_t current, uint32_t expected);
```

**Examples:**

```
current = 0b1010 (10), expected = 0b1001 (9) -> {flipCount: 2, highestFlipped: 1}
current = 0xFF00FF00,   expected = 0xFF00FF00 -> {flipCount: 0, highestFlipped: -1}
current = 0x00000000,   expected = 0x80000000 -> {flipCount: 1, highestFlipped: 31}
```

**Constraints:**

- `current` and `expected` are 32-bit unsigned values
- Bit 0 is the least significant bit; bit 31 is the most significant
- Target O(1) time and O(1) space (word-level bit tricks, no loops over the 32 bits if avoidable)
