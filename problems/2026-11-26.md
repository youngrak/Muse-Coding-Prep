## Problem 1: Critical Sensor Links in a Mesh Network

**Topic:** Graphs — Tarjan's bridge-finding algorithm (critical connections in an undirected graph)

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A sensor mesh has `n` nodes numbered `0` through `n - 1`, connected by undirected links given in `connections`, where each link `[a, b]` connects nodes `a` and `b`. A link is *critical* if removing it disconnects the mesh — that is, after removing the link, some node can no longer reach some other node. Return all critical links, in any order. Each link in the output should be a two-element list `[a, b]`; the order of `a` and `b` inside a link does not matter.

```cpp
std::vector<std::vector<int>> criticalSensorLinks(int n, const std::vector<std::vector<int>>& connections);
```

**Example 1:**

```
Input:  n = 4, connections = [[0, 1], [1, 2], [2, 0], [1, 3]]
Output: [[1, 3]]
Explanation: The links [0, 1], [1, 2], and [2, 0] form a triangle, so
removing any one of them leaves the three nodes still connected. Link
[1, 3] is the only bridge: removing it isolates node 3.
```

**Example 2:**

```
Input:  n = 2, connections = [[0, 1]]
Output: [[0, 1]]
Explanation: With a single link, removing it disconnects the two nodes.
```

**Example 3:**

```
Input:  n = 5, connections = [[0, 1], [1, 2], [2, 3], [3, 4], [4, 0]]
Output: []
Explanation: The five links form a single cycle, so no link is critical.
```

**Example 4:**

```
Input:  n = 6, connections = [[0, 1], [1, 2], [2, 0], [1, 3], [3, 4], [4, 5], [5, 3]]
Output: [[1, 3]]
Explanation: The triangle 0-1-2 and the triangle 3-4-5 each survive the
loss of any single link, but [1, 3] is the only connection between the
two triangles, so it is the only critical link.
```

**Constraints:**
- `2 <= n <= 10^5`
- `1 <= connections.size() <= 10^5`
- `connections[i].length == 2`
- `0 <= a, b < n` and `a != b` for every link `[a, b]`
- There are no duplicate links
- The mesh is connected (every node can reach every other node)
- Aim for O(V + E) time and O(V + E) extra space, where V is the number of nodes and E is the number of links

## Problem 2: Sensor Shard Consistent Hashing Ring

**Topic:** Design — consistent hashing ring with virtual nodes

**Statement:** Telemetry shards are distributed across gateway nodes using consistent hashing. Design a class `ConsistentHashRing` that maps each sensor key to the gateway node responsible for it.

The ring works as follows. Each physical gateway node owns `virtualNodesPerNode` virtual nodes on the ring. The hash of virtual node `i` (0-indexed) of node `node` is `std::hash<std::string>{}(node + "#" + std::to_string(i))`, and the hash of a key is `std::hash<std::string>{}(key)`. All virtual-node hashes are ordered around the ring; a key maps to the first virtual node whose hash is greater than or equal to the key's hash, wrapping around to the smallest hash if no virtual node's hash is large enough. The gateway node that owns that virtual node is the answer.

Implement:
- `ConsistentHashRing(int virtualNodesPerNode)` — constructs an empty ring with the given number of virtual nodes per physical node.
- `void addNode(const std::string& node)` — adds a node and all of its virtual nodes to the ring. Adding a node that is already present is a no-op.
- `void removeNode(const std::string& node)` — removes a node and all of its virtual nodes from the ring. Removing a node that is not present is a no-op.
- `std::string getNode(const std::string& key) const` — returns the gateway node responsible for `key`, or an empty string if the ring has no nodes.

```cpp
class ConsistentHashRing {
public:
    explicit ConsistentHashRing(int virtualNodesPerNode);
    void addNode(const std::string& node);
    void removeNode(const std::string& node);
    std::string getNode(const std::string& key) const;
};
```

**Example 1:**

```
Input:  ring = ConsistentHashRing(2); ring.addNode("gw-A");
        ring.getNode("sensor-1")
Output: "gw-A"
Explanation: With only one node on the ring, every key maps to it.
```

**Example 2:**

```
Input:  ring = ConsistentHashRing(2);
        ring.getNode("sensor-1")
Output: ""
Explanation: An empty ring has no node responsible for any key.
```

**Example 3:**

```
Input:  ring = ConsistentHashRing(2); ring.addNode("gw-A"); ring.addNode("gw-B");
        ring.removeNode("gw-A"); ring.getNode("sensor-1")
Output: "gw-B"
Explanation: After gw-A is removed, gw-B is the only node left, so every
key maps to it.
```

**Example 4:**

```
Input:  ring = ConsistentHashRing(2); ring.addNode("gw-A"); ring.addNode("gw-A");
        ring.getNode("sensor-9")
Output: "gw-A"
Explanation: Adding the same node twice is a no-op; the ring still holds
only gw-A.
```

**Constraints:**
- `1 <= virtualNodesPerNode <= 1000`
- The number of physical nodes on the ring is at most `10^4`
- The total number of `addNode`, `removeNode`, and `getNode` calls is at most `10^5`
- Node names and keys are non-empty strings of length at most 64
- Aim for O(log N) time per operation, where N is the total number of virtual nodes on the ring
