## Problem 1: Minimum Cost to Connect All Sensor Nodes

**Topic:** Graphs — minimum spanning tree (Prim's algorithm)

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A factory floor has `n` sensor nodes that must all be connected into a single mesh network. For some pairs of nodes `(u, v)`, a direct link can be laid at cost `w` (cable length / signal budget). A link can be used in either direction. Find the minimum total cost of a set of links that connects all `n` nodes, or return `-1` if the nodes cannot all be connected. The given links are guaranteed to have no self-loops, but there may be multiple links between the same pair of nodes with different costs.

```cpp
int minCostToConnectSensors(int n, std::vector<std::vector<int>>& links);
```

**Example 1:**

```
Input:  n = 4, links = [[0, 1, 10], [0, 2, 6], [0, 3, 5], [1, 3, 15], [2, 3, 4]]
Output: 19
Explanation: Use links (2,3,4), (0,3,5), (0,1,10) for a total of 19.
```

**Example 2:**

```
Input:  n = 3, links = [[0, 1, 5]]
Output: -1
Explanation: Node 2 is isolated, so the mesh cannot be connected.
```

**Example 3:**

```
Input:  n = 1, links = []
Output: 0
```

**Constraints:**
- `1 <= n <= 10^4`
- `0 <= links.size() <= 10^5`
- Each link is `[u, v, w]` with `0 <= u, v < n`, `u != v`, and `1 <= w <= 10^6`.
- If the graph cannot be connected, return `-1`.

## Problem 2: Sensor Calibration LFU Cache

**Topic:** Design — least frequently used (LFU) cache, O(1) operations

**Statement:** A sensor gateway keeps the calibration profiles of recently used sensors in a small cache so it does not have to reload them from flash. Implement an LFU (least frequently used) cache with capacity `capacity`: `get(key)` returns the cached value for `key`, or `-1` if the key is not cached; `put(key, value)` inserts or updates the value for `key`. Every `get` and every `put` of an existing key counts as one use of that key. When the cache is full and a new key must be inserted, evict the least frequently used key; if several keys share the lowest frequency, evict the least recently used among them. Both `get` and `put` must run in O(1) average time.

```cpp
class SensorLFUCache {
public:
    SensorLFUCache(int capacity);
    int get(int key);
    void put(int key, int value);
};
```

**Example:**

```
SensorLFUCache cache(2);
cache.put(1, 10);   // cache: {1:10}
cache.put(2, 20);   // cache: {1:10, 2:20}
cache.get(1);       // returns 10; key 1 now has frequency 2
cache.put(3, 30);   // cache is full; evicts key 2 (frequency 1 < 2); cache: {1:10, 3:30}
cache.get(2);       // returns -1 (evicted)
cache.get(3);       // returns 30
cache.put(4, 40);   // cache is full; key 1 (freq 2) and key 3 (freq 2) tie — evicts key 1 (least recently used)
cache.get(1);       // returns -1 (evicted)
cache.get(3);       // returns 30
cache.get(4);       // returns 40
```

**Constraints:**
- `0 <= capacity <= 10^4`
- `0 <= key <= 10^5`
- `0 <= value <= 10^9`
- At most `2 * 10^5` calls to `get` and `put` combined.
- `get` and `put` must each run in O(1) average time.
