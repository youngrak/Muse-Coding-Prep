## Problem 1: Firmware Command Transformation Ladder

**Topic:** Graphs / BFS — shortest transformation sequence between two commands

**Google Doc mode:** Solve this one in a plain text editor with no compiling — dry-run by hand.

**Statement:** A firmware device accepts a fixed dictionary of valid command words. A transformation step changes exactly one character of a command word to a different letter, and the result must be a valid command word from the dictionary. Given a start command `beginWord`, a target command `endWord`, and the dictionary `wordList`, return the number of words in the shortest transformation sequence from `beginWord` to `endWord` (counting both endpoints). If no such sequence exists, return 0. The dictionary may or may not contain `endWord`. Aim for O(N * L^2) time where N is the number of words in `wordList` and L is the word length.

```cpp
int commandLadderLength(const std::string& beginWord, const std::string& endWord, const std::vector<std::string>& wordList);
```

**Example 1:**

```
Input:  beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log","cog"]
Output: 5
Explanation: One shortest sequence is "hit" -> "hot" -> "dot" -> "dog" -> "cog".
```

**Example 2:**

```
Input:  beginWord = "hit", endWord = "cog", wordList = ["hot","dot","dog","lot","log"]
Output: 0
Explanation: "cog" is not in the dictionary, so no sequence reaches it.
```

**Example 3:**

```
Input:  beginWord = "cold", endWord = "warm", wordList = ["cord","card","ward","warm"]
Output: 5
Explanation: "cold" -> "cord" -> "card" -> "ward" -> "warm" is a shortest sequence.
```

**Example 4:**

```
Input:  beginWord = "a", endWord = "c", wordList = ["a","b","c"]
Output: 2
Explanation: "a" -> "c" is a single step, and the sequence has two words.
```

**Constraints:**
- `1 <= beginWord.size() == endWord.size() <= 10`
- `1 <= wordList.size() <= 5000`
- `wordList[i]` has the same length as `beginWord`
- `beginWord`, `endWord`, and every word in `wordList` consist of lowercase English letters
- Aim for O(N * L^2) time and O(N * L) extra space

## Problem 2: Randomized Sensor Sampler

**Topic:** Design — O(1) insert, remove, and uniform random sampling

**Statement:** Design a class `SensorSampler` that holds a set of distinct sensor IDs (32-bit integers) and supports three operations, each in O(1) average time: `insert(id)` adds an ID and returns `true` if it was not already present (otherwise returns `false` and changes nothing); `remove(id)` deletes an ID and returns `true` if it was present (otherwise returns `false`); `getRandom()` returns one of the currently stored IDs, chosen uniformly at random. `getRandom()` is only called when the set is non-empty. Use only standard containers — no precomputed permutation tricks that cost more than O(1) amortized per call.

```cpp
class SensorSampler {
public:
    bool insert(int id);
    bool remove(int id);
    int getRandom();
};
```

**Example 1:**

```
Input:
SensorSampler sampler;
sampler.insert(10);   // returns true
sampler.insert(20);   // returns true
sampler.insert(10);   // returns false (10 is already present)
sampler.getRandom();  // returns 10 or 20 (uniformly at random)
sampler.remove(10);   // returns true
sampler.remove(10);   // returns false (10 is already gone)
sampler.getRandom();  // returns 20 (the only ID left)
```

**Example 2:**

```
Input:
SensorSampler sampler;
sampler.insert(7);    // returns true
sampler.getRandom();  // returns 7
sampler.remove(7);    // returns true
sampler.insert(-3);   // returns true
sampler.getRandom();  // returns -3
```

**Constraints:**
- `-2^31 <= id <= 2^31 - 1`
- At most `2 * 10^5` total calls to `insert`, `remove`, and `getRandom`
- `getRandom` is called only when at least one ID is present
- Each operation must run in O(1) average time
