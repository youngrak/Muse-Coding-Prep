## Problem 1: Telemetry Buffer Partition

*Topic: Two pointers — in-place partition*

An onboard telemetry buffer holds `samples`, a list of integer sensor readings. Readings below `threshold` are critical alerts that must be DMA-transferred first. Reorder the buffer in place so that every critical reading (value < threshold) appears before every non-critical reading (value >= threshold). The relative order within each group does not matter.

Required signature:

```cpp
void partitionCritical(std::vector<int>& samples, int threshold);
```

Examples:

```
samples = [7, 2, 9, 4, 5], threshold = 5  ->  [4, 2, 9, 7, 5] (any arrangement with <5 first)
samples = [3, 1, 2],       threshold = 10 ->  [3, 1, 2]      (all critical)
samples = [5, 6, 7],       threshold = 5  ->  [5, 6, 7]      (none critical)
```

Constraints:

- 0 <= samples.size() <= 10^6
- -2^31 <= sample value <= 2^31 - 1
- Reorder in place: O(n) time, O(1) extra space
- Relative order within the two groups is not required

## Problem 2: Interrupt Call-Stack Validation

*Topic: Stacks — validate a pop order*

**[Google Doc mode: solve in a plain text editor with no compiling; dry-run your code by hand.]**

On the device, interrupt handlers push event IDs onto a call stack in a recorded push order and pop them in a recorded pop order. Given `pushed` (event IDs in push order) and `popped` (event IDs in pop order), determine whether the pop order is actually possible under stack (LIFO) discipline. Every event ID is unique; `pushed` and `popped` contain exactly the same IDs.

Required signature:

```cpp
bool isValidPopOrder(const std::vector<int>& pushed, const std::vector<int>& popped);
```

Examples:

```
pushed = [1,2,3,4,5], popped = [4,5,3,2,1]  ->  true
pushed = [1,2,3,4,5], popped = [4,3,5,1,2]  ->  false
pushed = [],          popped = []           ->  true
```

Constraints:

- 0 <= pushed.size() <= 10^5
- pushed.size() == popped.size()
- Event IDs are unique; both sequences hold the same IDs
- Target O(n) time, O(n) extra space
